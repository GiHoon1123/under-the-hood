# 트랜잭션 검증·실행·수수료 흐름

상태: 초안 · 공개 블록체인 구조 기준

## 검증과 실행은 다르다

```text
검증: 이 요청을 실행해도 되는가?
실행: 실행하면 상태가 어떻게 바뀌는가?
```

서명이 유효해도 잔액이 부족하면 실행할 수 없고, 잔액이 충분해도 계약 실행 중 revert가
발생할 수 있다.

## 사전 검사

```text
트랜잭션 인코딩 · 서명 · chain ID · nonce 또는 sequence
잔액 · 최대 수수료 · gas limit
```

이 검사는 mempool에 넣기 전에 수행할 수 있지만 최종 상태를 확정하지는 않는다.

## Nonce

계정의 nonce는 트랜잭션 순서와 재사용 여부를 나타낸다. 현재 nonce가 7이면 보통 nonce 7인
다음 트랜잭션을 처리하고, 처리 후 현재 nonce는 8이 된다. 이미 사용한 nonce 7을 다시
제출하면 오래된 트랜잭션으로 처리한다.

nonce 8이 먼저 도착하면 mempool에서 보류하거나 거부할 수 있다. 최종 실행은 계정별 순서를
지켜야 한다.

## Gas limit과 gas used

`gasLimit`은 트랜잭션이 사용할 수 있는 최대 실행량이고, `gasUsed`는 실제 사용량이다.
예를 들어 gasLimit이 100,000이고 gasUsed가 40,000이면 실제 실행은 40,000 가스를 사용한
것이다.

블록 전체에도 `max_gas`가 있을 수 있다. 블록에 이미 900,000 gas를 사용했고 다음 트랜잭션이
200,000 gas를 요구한다면 `max_gas = 1,000,000`인 블록에는 포함할 수 없다.

`max_bytes`는 바이트 크기 제한이고 `max_gas`는 실행량 제한이라 서로 다르다.

## 수수료

일반적인 개념식은 `fee = gasUsed × gasPrice`다. EIP-1559에서는 base fee와 priority fee를
구분해 유효 gas price를 계산한다.

최대 수수료를 지불할 잔액이 있는지 먼저 확인하고 실제 사용량에 따라 최종 비용을 계산한다.
즉 최대 예약 비용은 `gasLimit × 최대 gas price`, 실제 비용은 `gasUsed × 유효 gas price`다.

## 실행과 rollback

```text
Snapshot → 계정·storage 변경 → 계약 실행
```

성공하면 변경을 유지하고, revert나 out-of-gas가 발생하면 상태 변경을 snapshot으로 되돌릴
수 있다. 하지만 이미 수행한 계산 비용은 청구될 수 있다.

```text
상태 변경 → rollback 가능
사용한 계산 자원 → 비용 청구 가능
```

## 트랜잭션과 상태 머신

```text
Sₙ + tx1 → 중간 상태
중간 상태 + tx2 → 다음 중간 상태
```

따라서 블록 내 순서가 바뀌면 nonce·잔액·가스 결과가 바뀔 수 있다.

## 정리

```text
사전 검사 → mempool → 합의 → 순서대로 실행
→ gasUsed 계산 → 상태 성공/rollback
→ 수수료 반영 → 블록 Commit
```

## `CheckTx`와 실제 실행 사이

두 트랜잭션이 제출 시점에 같은 잔액을 보고 각각 사전 검사를 통과할 수 있어도, 블록에서는
앞선 트랜잭션이 상태를 바꾼 뒤 실행된다.

```text
초기 Alice = 100
tx1: Alice → Bob 80
tx2: Alice → Carol 50
```

tx1이 먼저 실행되면 tx2 시점의 잔액은 20이다. 따라서 사전 검사 성공과 최종 실행 성공을
같은 의미로 보면 안 된다.

## 블록 크기와 가스 한도

트랜잭션 크기는 직렬화된 byte length다. 블록은 헤더와 evidence 같은 오버헤드도 포함하므로
`max_bytes` 전체를 트랜잭션에 사용할 수 없다.

```text
max_bytes = 바이트 크기 제한
max_gas   = 전체 실행량 제한
```

바이트 공간이 남아도 `max_gas`를 넘으면 다음 트랜잭션을 넣을 수 없다. 실제 파라미터는
네트워크 설정과 합의 파라미터 변경으로 결정된다.

## 수수료와 실패

최대 예약 비용은 보통 `gasLimit × 최대 gas price`로 계산해 잔액을 사전 확인하고, 실행 후
실제 비용은 `gasUsed × 유효 gas price`로 계산한다. 계약이 revert하면 상태 변경은 되돌아가도
이미 사용한 계산 자원에 대한 수수료는 체인 규칙에 따라 청구될 수 있다.
